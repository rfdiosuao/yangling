## 0. 一句话结论

**能复用的开源轮子直接复用,别自己造;但「结构化知识库 + 规则引擎 + 东方美学 UI」是我们的护城河,必须自造。** UI 从 6 页平铺收拢为 4 主导航 + 三卡执行器,让每条功能都有明确入口和退路,demo 不迷路。

## 一、开源选型调研(2026-07 检索)

> 原则:能直接复用就用;能用轻量的就不用重框架;凡是涉及"中医可审、医学可信"的核心逻辑,一律不外包给黑盒。

### 1.1 检索引擎(结论:保持现状,不换)

| 项目 | 说明 | Star 量级 | 许可证 | 判断 |
|---|---|---|---|---|
| **MiniSearch** | 内存全文检索,前缀/模糊/字段加权 | ~4.6k | MIT | ✅ **复用**(已用)。4600 条本地语料正是它的甜点区 |
| FlexSearch | 速度最快的 JS 全文检索 | ~12k | Apache-2.0 | 📎 参考。10 万+ 条才显优势,当前量级收益小 |
| Orama(原 Lyra) | 全文+向量+混合一站式 | ~9k | Apache-2.0 | 📎 参考。要"语义召回"再评估 |
| Voy | WASM 向量检索 | ~1.2k | MIT | 📎 参考。仅需向量相似度时才用 |
| LangChain.js / LlamaIndex.TS | 重框架 | 16k+ / 周下载 40 万 | MIT | ❌ 不采用。为"卡片检索"引入过重,徒增维护成本 |

**结论**:MiniSearch 保留,不引入任何向量库/重框架。当前瓶颈是 bundle 体积(1.07MB gzip),不是检索能力。

### 1.2 AI 对话 UI 组件(结论:不引入,仅参考交互范式)

| 项目 | 说明 | Star 量级 | 判断 |
|---|---|---|---|
| **assistant-ui** | ChatGPT 式可组合原语(shadcn/ui + Tailwind) | ~12k | 📎 参考流式/无障碍范式,**不引入**(捆绑 Tailwind,主题覆写成本 > 自写收益) |
| CopilotKit | 应用内 Copilot/Agent 基建 + 生成式 UI | ~37k | 📎 参考,偏重 |
| nlux | 轻量对话 UI | — | 📎 参考,生态弱 |
| @chatscope/chat-ui-kit-react | 聊天 UI 套件 | ~2k | ❌ 不采用,更新慢、风格老 |

**结论**:聊天框自写,仅借鉴 assistant-ui 的流式渲染、自动滚动、无障碍交互思路。我们的对话入口是"引导式追问 + 卡片预览",不是通用聊天,自写反而更贴合产品。

### 1.3 节气/农历(结论:直接复用,替换硬编码)

| 项目 | 说明 | 判断 |
|---|---|---|
| **lunar-javascript(6tail)** | 农历/节气/干支/宜忌全量,零依赖 | ✅ **复用**。当前首页"白露 · 秋金"是写死的,这是最该替换的硬编码 |
| solarlunar / lunisolar | 备选农历库 | 📎 参考,功能重叠,选其一 |

**结论**:接入 lunar-javascript,节气、干支、当前时辰全部动态计算,真正实现"顺时而养"。

### 1.4 日历/打卡(结论:复用轻量组件)

| 项目 | 说明 | Star 量级 | 判断 |
|---|---|---|---|
| **react-day-picker** | shadcn 日历同款底座,主题可控 | ~6.4k | ✅ **复用**。做"7 天横向养生日历"最合适 |
| **dayjs** | 2KB 日期库 | ~48k | ✅ **复用**。日期计算/格式化 |
| react-calendar | 功能全 | ~8k | 📎 参考,定制偏 CSS 折腾 |
| FullCalendar / react-big-calendar | 面向日程排期 | 20k+ | ❌ 不采用,7 天打卡是"网格+热力",过重 |

### 1.5 体质数据(结论:作为规范依据)

| 项目 | 说明 | 判断 |
|---|---|---|
| **GB/T 46939—2025《中医体质分类与判定》** | 2025-12-31 发布、2026-04-01 实施,9 种体质特征 + 判定计分 | ✅ **复用(数据规范)**。直接作为知识库规范和"体质问卷"设计依据,优于旧版标准 |
| 养生宝 yangshengbao | 九种体质 + 60 题问卷 + 舌象规则(FastAPI+Flutter) | 📎 参考知识库结构 |
| MTCMB | 中医多任务评测基准(7100 样本) | 📎 参考,偏评测数据 |

### 1.6 姿态识别(结论:保持现状)

| 项目 | 说明 | 判断 |
|---|---|---|
| **@mediapipe/tasks-vision** | PoseLandmarker/BlazePose,33 关键点 + 3D,浏览器原生 GPU | ✅ **复用**(已用)。Web 端姿态检测最成熟封装,别换 |
| tfjs-models pose-detection | MoveNet/BlazePose 统一入口 | 📎 参考,要 MoveNet 再用 |
| Workout-tracker 等 | MediaPipe 计数/评分示例 | 📎 参考动作识别规则(角度阈值+计数)算法 |

## 二、必须自造的三样(护城河)

开源世界只有零散素材,没有现成整包,这三样是我们差异化所在:

1. **结构化养命知识库**:4600 条卡片切片,含「节气 × 时辰 × 体质 × 证候」的多维关联 schema(knowledge.json + docs.js + papers.js 三源)。
2. **规则引擎**:节气 × 体质 × 作息 → 个性化方案的确定性推理,医学可审、不会胡说(这是规避"AI 乱给医疗建议"的架构根基)。
3. **东方美学 UI 主题层**:米白宣纸底 + 墨色 + 随节气变主色 + 流体呼吸背景,在所有开源组件之上覆写一层养令专属皮肤。

---

## 三、现有 UI 逻辑的六个问题

1. **6 页平铺导航,主次不分**:评委 4 分钟 demo 找不到重点。
2. **功能重复**:家庭守护页 vs 卡片页"给爸妈版"toggle,两处做同一件事。
3. **功能错位**:睡前时辰(呼吸练习)本质是"一息"卡的执行器,却独立成页,和时序卡割裂。
4. **好功能被藏**:姿态识别 PoseGuide 埋在卡片页角落,这是唯一有"现场动作演示"效果的功能,评委看不到。
5. **硬编码**:节气、时辰写死在文案里,没有真正"顺时"。
6. **采集缺失**:卖点是"九种体质",但产品里没有任何体质判定入口。

## 四、重划后的 UI 呈现逻辑

### 4.1 主导航:6 → 4

| 新导航 | 定位 | 吸收的旧页 |
|---|---|---|
| **今日** | 仪表盘(主链路核心) | 原卡片页的"总览+打卡" |
| **说状态** | 对话采集(入口) | 原说状态页 |
| **养生日历** | 沉淀(7天+趋势) | 原养生日历页 |
| **家庭守护** | 分享 | 原家庭守护页 + 卡片页"给爸妈版"toggle |

> 原「睡前时辰」并入"一息"执行器,不再独立成页。

### 4.2 核心重构:方案卡 → 真·执行中心

**今日(仪表盘)顶部三要素一眼可见**:当前节气 · 当前时辰 · 体质 → **三卡总览**(一杯/一动/一息,带完成态)→ **一键打卡** → **给爸妈版按钮**。首页的时辰罗盘挪到这里,高亮当前时辰,不再是装饰。

三卡点击进执行器(这是关键变化):

| 执行器 | 内容 |
|---|---|
| **一杯** | 食材清单 + 步骤卡 + 3 分钟冲泡计时器 + "为什么管用"(带引用) |
| **一动** | 穴位定位图 + 姿态查验(摄像头 + MediaPipe 打分),从隐蔽角落变成主入口 |
| **一息** | 呼吸循环引导动画(原睡前时辰页整体并入),可选 4-7-8 / 腹式呼吸 |

### 4.3 各页要点

- **说状态**:保留对话,但"状态抽取不完整"时用引导式追问气泡(睡眠/嘴苦/压力三个快捷项),降低自然语言门槛;回答直接在对话里渲染时序卡预览 + 一键跳"今日"。
- **养生日历**:7 天打卡热力 + 体质趋势,明示"数据仅存本机、可清除"(合规亮点)。
- **家庭守护**:大字号口语化 + 一键复制/微信分享,吸收原 toggle。

### 4.4 一句话动线

**说状态造卡 → 今日执行打卡 → 日历沉淀家庭分享**,每个功能都有明确入口和退路。
