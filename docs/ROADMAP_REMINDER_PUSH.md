> **复客松 · 华润三九杯 AI 医疗健康黑客松**(2026.9.10–13)
> 需求提出：2026-09-07 · 状态：**路线规划（未实现，未写代码）**
> 定位：把「主动提醒 + 独特别称 + 使用时长记录 + 到点叫回来养生」这条需求，拆成可执行的分阶段路线。
> 约定：本文档只规划路线，**不在本次落地任何代码**；每个阶段都写清「做什么 / 用什么 / 怎么验收」。

## 0. 需求一句话

**养令要变成"会主动找你的养生 App"：给每个用户起一个独特别称，记录他在养令里待了多久，到点（他自己定或系统推断）弹一条通知把他叫回来养生，点通知直达对应的养生动作。**

---

## 1. 用户故事（口语化，给队友评审用）

- 作为用户，我打开养令，它先给我起个专属昵称（比如"白露·秋金令主"），后面都用这个称呼我。
- 养令偷偷记着我在里面用了多久（今天累计 47 分钟了）。
- 到时间了（我设的 45 分钟，或它观察出我的作息推断），它弹通知："阿令，你已经看了 47 分钟，起来做一次「一息」，不然身体要废啦～"。
- 我**没打开养令、甚至关了页面**，也能收到这条通知（这才是"主动推送"）。
- 我点一下通知，直接进入对应的「一杯 / 一动 / 一息」执行器，做完打个卡。
- 家长版用户看到的是**更大字、更口语**的版本："闺女，该起来动动了"。

## 3. 为什么走 PWA 路线（选型结论）

| 路径 | 没打开也能弹 | 开发量 | 后端 | 结论 |
|---|---|---|---|---|
| A · 页面内提醒 | ❌ | 极小 | 无 | P0 先用它跑通逻辑 |
| **B · PWA 推送** | ✅ | 小 | 需一个小推送服务 | **本次主路线** |
| C · 原生 App | ✅ 最稳 | 大 | APNs/FCM | 赛后可做 |

**选定 B 的理由**：现有代码是 React/Vite 网页，PWA 化（manifest + Service Worker）几乎不改业务代码；Web Push 是浏览器原生能力，Android/Chrome 成熟，iOS 16.4+ 也支持。

## 4. 目标技术架构（B 路线的样子）

```
[用户手机/电脑]
   ├─ 养令 PWA（现有 React 代码 + 新增）
   │     ├─ 使用时长记录：session 计时 → localStorage 累计
   │     ├─ 独特别称生成：规则模板（体质×节气×随机）
   │     ├─ 提醒设置：间隔/时段（用户自设 + 作息推断）
   │     └─ Service Worker：注册、缓存、push 事件、notificationclick
   └─ 浏览器系统通知栏 ← 推送消息在这里弹出（页面没开也能弹）

[推送服务器（本次新增的最小后端）]
   ├─ 保存订阅（PushSubscription + 用户自定义提醒时间）
   ├─ 定时任务：到点调 Web Push 接口发消息
   └─ VAPID 密钥对（公钥给前端，私钥在服务端）

[浏览器自带推送通道]（Chrome= FCM / Safari= APNs 适配）
   ← 服务器把消息递给它，它递到系统通知栏
```

**数据流一句话**：打开→授权通知→记时长→（本地或服务器）到点→推送服务器→浏览器通道→系统通知栏弹出→点击直达养生卡。

## 5. 分阶段路线图

### P0 · 本地提醒闭环（纯前端，0 后端）—— 黑客松前必须完成

**做什么**
1. 使用时长记录：页面打开计时，累计存 localStorage，会话间不丢。
2. 独特别称生成器：模板如 `{节气}·{体质}{后缀}`，产物有彩蛋感（用户偏好：品牌字用 running script 字体）。
3. 提醒设置页：用户设「每 N 分钟提醒一次」+ 可选时段。
4. 页面内通知：`Notification API` + 提示音（复用 ambient-audio 思路），点通知直达对应 tab。
5. 文案模板库 + 安全门禁过滤：所有提醒文案过 `checkRisk`，语气"督促但有温度"，不做医疗恐吓（"身体要废了"是玩笑，但要保证不触发红旗词、不制造焦虑）。

**用什么**：`Notification API`、`localStorage`、现有 `src/mobile/*`、现有 `src/core/safety`。
**验收**：开着页面，到达设定时长弹出通知，点击直达对应执行器；别称在首页和通知里一致；测试通过。

---

### P1 · PWA 化 + 真推送（本次核心，需要一个小后端）

**做什么**
1. PWA 化：`manifest.json`（图标/名称/主题色）+ 可安装到主屏。
2. Service Worker：缓存静态资源 + 监听 `push` + `notificationclick`。
3. 订阅链路：`PushManager.subscribe`（用 VAPID 公钥）→ 订阅信息存服务器。
4. 推送服务器选型（**先实测国内可用性再定**）：
   - 方案甲：**自建轻量推送**——Cloudflare Workers / 火山引擎 veFaaS 上跑一个函数 + `web-push` 库 + VAPID 密钥，定时任务到点推送。数据不离开自己控制范围。
   - 方案乙：**托管服务**——OneSignal / Firebase FCM。接入快，但服务器在境外，**涉及健康相关数据，有合规与连通性风险**，赛前必须实测。
5. 调度策略：
   - 先做「**本地调度**」：Service Worker 内定时（`setTimeout`/`showTrigger`），服务器仅转发——最简单的"关页也能弹"。
   - 后补「**服务端调度**」：服务器存提醒时间，到点推送——手机重启/浏览器退出也稳。
6. 国内可用性实测（**关键验收**）：Chrome 桌面 / 安卓 Chrome / iOS Safari（需先加到主屏）各弹一次。

**用什么**：`manifest.json`、`service-worker.js`、`Push API`、`web-push`(Node)、Cloudflare Workers 或 veFaaS、VAPID。
**验收**：**关掉页面后仍能收到通知**；点击通知直达对应养生卡；三端（桌面 Chrome / 安卓 / iOS 16.4+）至少两端通过。

---

### P2 · 个性化与养成（在 P1 之上加分）

1. **作息学习**：记录用户活跃时段，推断「提醒时段建议」并给出默认。
2. **别称进化**：别称绑定节气流转 + 体质，节气变了别称跟着变（呼应"顺时而养"）。
3. **断卡提醒**：结合养生日历，连续 N 天没打卡时推"回归"提醒。
4. **家长版提醒**：大字 + 口语化 + 可一键转发微信（仅静态文案，不携带画像，合规）。
5. **文案 A/B**：督促系 / 温情系两套模板轮换，降低通知疲劳。

**验收**：提醒时段贴合用户真实作息；断卡提醒生效；家长版文字可读。

---

### P3 · 可选：原生 App 化（赛后再说）

- 时机：黑客松结束、验证有留存后。
- 备选栈：React Native / Flutter 复用现有逻辑；推送走 APNs/FCM，最稳，且能申请屏幕使用时间权限。
- 现在**不做**：开发量大，赛前做是负资产。

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| **国内 Web Push 通道不稳定**（Chrome 走 FCM，需能连通） | 高 | P1 第一步就是实测；不通则退回"本地调度 + 页面内提醒"演示，服务器转发作为保底路径 |
| iOS 必须"添加到主屏"才收推送 | 中 | 引导文案 + 首启教学步骤 |
| 安卓国产 ROM 杀后台 / 限制 PWA | 中 | 声明支持范围；原生 App 作为 P3 兜底 |
| 通知权限拒绝率高 | 中 | 首次引导讲清价值（"到点叫你起来动一动"）；拒绝后可重开 |
| 提醒文案踩医疗红线 | 高 | 所有文案过 `checkRisk` 门禁 + 医学成员审核措辞库 |
| 第三方推送服务数据出境（健康数据合规） | 中 | 优先自建（veFaaS/Workers）；用托管服务前先过合规评估 |
| 通知疲劳 / 打扰 | 中 | 默认低频（每 45 分钟+）+ 可关；A/B 文案 |

---

## 8. 不做清单（防跑偏）

- ❌ 不读手机**整体**屏幕使用时间（浏览器沙箱技术上做不到；原生 App 才有，且需敏感授权）。
- ❌ 赛前不做原生 App、不做账号体系、不做云端用户画像（数据只存本机）。
- ❌ 不把提醒做成强医疗建议（安全门禁兜底）。
