# 养令 · 口播稿创作方法论：痛点 → 过程 → 升华（三段式 SOP）

2026-09-13 调研修订版 · 适用：黑客松路演视频配音稿、现场宣讲稿、Demo 解说稿

> **默认骨架：痛点 → 功能证明（使用过程）→ 价值升华。实际赛规优先。**
> 它不是某一篇稿子，而是写稿的"模具"：先套骨架，再填内容。
> 当前范例见[养令三段式口播·功能证据版](养令三段式口播-功能证据版-2026-09-13.md)。旧现场稿与视频稿仅作历史参考，使用前须按第 10 节复核。

---

## 0. 理论来源：把高考作文那套搬过来

评委听路演与阅卷老师读答案有一个可借鉴的共同点：表达者要让对方容易识别自己的观点和依据。但两者不是同一套评价体系，也没有查到“前 30 秒定档”的通用依据。

本方法借语文大题的“审题、分点、给依据”，借作文的“扣题、展开、呼应”。教育部教育考试院的试题评析强调思维严密与表达准确，而非机械记忆套路。[来源 S1]

**一句话核心：把评分表当题目，把可运行的产品当材料，把路演当有证据的作答。** 下表是团队迁移方法，不是高考评分细则：

| 高考作文技法 | 对应到口播稿 | 回答的问题 |
|---|---|---|
| **凤头**（开头要漂亮、破题快） | **第一段 · 痛点** | 这是个真问题吗？跟我有关吗？ |
| **猪肚**（中间内容充实、条理清楚） | **第二段 · 使用过程（功能）** | 你怎么解决？我怎么用？真的能用吗？ |
| **豹尾**（结尾有力、余味长） | **第三段 · 升华** | 你做这件事的意义是什么？我记住了什么？ |
| 议论文常见组织方式：提出问题—分析问题—解决问题 | 痛点（提出）→ 过程（解决）→ 升华（回收+拔高） | 全篇逻辑链 |
| 起承转合 | 痛点起 → 理念承 → 演示转（含家庭线、底线）→ 升华合 | 四段式节奏 |
| 以小见大 | 从"一句我没事/一颗枸杞"的生活切片，讲到健康服务千人千面 | 切入点选择 |
| 首尾呼应 | 开头"我没事只能靠猜" → 结尾"不再只能靠猜" | 闭环感 |
| 事实论证 + 分析 | 问卷原始记录 + 演示画面 + 解释其意义；头衔不能替代审核记录 | 可信度 |
| 对比论证 | 相同任务下展示旧流程与新流程，不虚构竞品能力 | 差异化 |
| 感情真挚、思想健康 | 真实经历、温柔语气、不越界诊断 | 合规底线 |
| 审题扣题 | 赛题关键词必须在稿中"响"（千人千面、银发守护） | 扣题分 |
| 线索贯穿 | 一个意象走到底（养令=小芽/小铃铛；温度线 凉→暖→更暖） | 记忆点 |

**一句话记住：凤头抛痛点，猪肚演过程，豹尾收价值。**

## 1. 总骨架与配比

### 先讲第一性：高分来自什么

**在题目与规则的约束下，给出有质量的回答，并让阅卷者容易识别、判断它的质量。** 这是本文的综合方法，不是官方“高分公式”。表达清楚能减少成果被漏看的机会，不能替代成果本身。

- **阅读主观大题：** 问什么就答什么，结论准确、要点完整，结合材料说明依据；分点是为了呈现不同有效信息，不是同一句话换着说。
- **作文：** 回应材料与写作任务，有明确立意，用具体材料和推理展开，语言准确、结构连贯；深度来自把关系与条件想清楚，不是堆名言或结尾突然拔高。官方试题评析强调思考与表达，也保留个性化写作空间，不能把作文等同于固定关键词填空。[来源 S1]
- **迁移到黑客松：** 先确认要评什么，再做出相应成果，最后让评委看到证据。审题对应赛规，论点对应产品主张，论据对应真实 Demo 与验证，首尾呼应对应用户问题的闭环。

一句话记忆：**先答对题，再把答案做实，最后让人看得明白。** 不是猜评委喜好，而是降低评委理解与核验的成本。

以下是排练起点，不是官方比例。短开场交代清楚对象和产品，给演示留主要时间；不要让评委等到半场才知道你做了什么。[来源 S2]

| 段 | 名称 | 占比（4 分钟稿） | 字数（约 900 字） | 必答问题 |
|---|---|---|---|---|
| 一 | **痛点**（凤头） | 0:00–0:40，40 秒 | 约 120–150 字 | 谁在什么场景受阻？产品是什么？ |
| 二 | **功能证明**（猪肚） | 0:40–3:25，165 秒 | 按演示停顿倒推 | 输入什么、得到什么、为何有用？ |
| 三 | **升华**（豹尾） | 3:25–4:00，35 秒 | 约 90–120 字 | 回到哪个人的改变？希望观众做什么？ |

> 三段是叙事逻辑，不强迫只有三页 PPT。若主办方要求先 Demo，就用一句痛点立即演示；若评分明确考商业性，则给商业验证留时间。技术权重高时，增加技术难点与实现证据，而不是增加抒情。

## 2. 第一段 · 凤头 = 痛点（尽快进入产品）

### 2.1 这一段要走完的五步（按顺序）

1. **设问/场景开场**——不寒暄、不自报家门式堆砌，第一句话就把听众拉进画面。
   - 句式："你有多久，没……了？" / "你有没有发现……"
2. **白描一个生活切片**（以小见大）——具体人物 + 具体动作，忌形容词堆砌。
   - 养令实例：爸妈总说"我没事" / 深夜刷完手机往保温杯丢枸杞 / 闹钟响了翻身按掉。
3. **回应赛题要求**（审题扣题，不借头衔代替论证）。
   - 养令实例："一边熬夜一边泡脚"——赛题发布会。
4. **给最相关的一条证据**（优先 1–2 个数字，必须说明样本量、题目和分母）。
   - 若要沿用旧稿的 41 份问卷，先复核原始答卷、有效样本和多选题口径；本轮未重算，示范稿不沿用这些数字。小样本只能说明受访者反馈，不能外推所有用户，更不能充当产品有效性的证明。
5. **一句话亮中心论点**（议论文的"立论"）。
   - 句式："所以，我们做了 X：不是……，而是……。"
   - 养令实例："所以我们做了养令：不是再给你一篇文章，而是把今天该做什么、怎么做、做得怎么样，直接摆到你面前。"

### 2.2 雷区

- ❌ 开头先讲团队、讲愿景、讲技术栈（评委还不知道你解决什么问题）。
- ❌ "随着社会发展、人们生活水平提高……"式空话开头。
- ❌ 只报百分比不说明分母；把不同题目的比例拼成因果关系。
- ❌ 痛点和后面的功能对不上（开头说 A 痛，中间全在演示 B）。

## 3. 第二段 · 猪肚 = 使用过程（中间 6 成时间，全篇得分段）

### 3.1 内部节奏：承 → 转（演示）→ 守（边界）

**① 承 · 一句话理念 + 对比论证（约 25 秒）**
- 先用赛题的问题接棒："能不能从千人一面，变成千人千面？"
- 立刻给答案，且用**对比**让差异肉眼可见。例如：从“看完文章不知道下一步”，到“点开卡片直接开始练习”。这属于用户流程对比，不代表所有竞品都缺少此能力。
- 不把“四种体质对应四种药茶”作为未经核验的功能示例；个体化健康建议需要核验输入、规则与适用条件，不能为了扣“千人千面”强行演示未实现能力。
- 句式："不是……，而是……。"

**② 转 · 分镜式操作流："三步带你用一遍"（约 70–90 秒，最重头）**
- 严格按**用户操作的时间顺序**写（说明文的程序顺序），第一步、第二步、第三步，评委脑子里能跟着点。
- 每一个功能点都用**功能三段式句式**：

  > **是什么**（功能名）→ **怎么用、屏幕上看到什么**（操作 + 画面）→ **解决第一段的哪个痛**（叙议结合，每段点一句就够）

  - 例 1：一杯一动一息 → 输入状态、点发送、查看建议 → 对应“不知道今天具体做什么”。引用知识库与 AI 通用建议必须按实际界面分别说明，不说每张卡都有来源。
  - 例 2：摄像头纠正 → 授权、真人入镜、骨架点、练偏提示/练到位开花 → 解决"没人纠正"。
  - 例 3：呼吸 + 本机提醒 + 7/14/30 天小芽成长 → 解决"坚持不下来、忙起来就忘"。
- **诚实演示原则**：说"先授权再识别"这种真实步骤；规划中的功能（手表/手环）用"下一步"，绝不包装成已上线。

**③ 转 · 副赛道/情感功能（约 25 秒）**
- 家庭线沿用同一套句式：引用扣题（"父母想独立，子女想放心"）→ 怎么绑定、能看见什么 → 边界（双方同意、非病历非监控、随时解绑）。

**④ 守 · 底线与未来（约 20 秒，议论文的"论证严密性"）**
- 只讲与本次演示有关的边界：本地姿态识别、知识依据与通用建议的区分、当前能力与计划的区分。人员资质及专业审核须有对应证据，不把“有医学队友”说成“每条答案都经过医学审核”。
- 未来硬件只说"下一步"：持续异常 → **提醒就医**，"不诊断、不处方、不替代检查"。
- 句式："X 负责……；医院负责……。"（责任划界，显得清醒可信）

### 3.2 详略原则（高考作文的"详略得当"）

- **核心闭环（输入→三卡片→摄像头→成长）详写**，每个动作给 2–4 秒画面停留；
- 技术、商业按本场评分权重分配时间；不要因为套三段式漏掉高权重评分项；
- 同一件事不重复抒情——车轱辘话是口播稿最大的字数杀手。

### 3.3 雷区

- ❌ 功能罗列成参数表（"我们有 A、B、C、D 功能"），没有操作流、没有画面。
- ❌ 只演示不回扣痛点（评委要听到"这治的是刚才哪个病"）。
- ❌ 把规划说成已上线；省略摄像头授权等真实步骤。
- ❌ 中间段占比不到一半——猪肚不充实，全篇立不住。

## 4. 第三段 · 豹尾 = 升华（短而有回收）

### 4.1 四步收束（按顺序）

1. **回收痛点**（首尾呼应）：把第一段抛的问题，用"三个具体问题"重新点一遍——今天该做什么 / 动作对不对 / 家人知不知道。**问题要和开头逐一对得上。**
2. **亮已完成结果**（可选，一句话）：可打开的网址、可安装的版本、可重复的演示。人数、天数、预算、赛期内新增内容须核实；有旧代码或付费资源就不要说“从零、零预算”。
3. **划界表态**（思想健康、反衬可信）："我们不替医生下结论，也不让家人互相监控。"
4. **金句定格**：从产品功能升到人的情感，slogan 短句收尾。
   - 公式：**具体动作/意象 + 情感结果**，不要空喊"大爱/感恩"。
   - 养令实例："让一句'我没事'，不再只能靠猜。" → "养令——练对、看见、有人惦记。"

### 4.2 金句怎么练

- 从开头埋的意象里收（开头"我没事"，结尾就还"我没事"）。
- 短句：8–14 字，能上墙、能做 PPT 封底。
- 先写 3 个备选，选最具体、最不像口号的那个。

### 4.3 雷区

- ❌ 结尾才开始讲新技术、新功能（豹尾不能塞新信息）。
- ❌ "谢谢聆听/感谢观看"式弱结尾，没有记忆句。
- ❌ 升华脱离产品喊口号（产品是养生陪伴，就别喊成科技改变人类）。

## 5. 贯穿全篇的三条暗线（写完必须回头检查）

1. **扣题线**：每个重点要求都能找到“回应它的功能与证据”。关键词出现几次不是得分依据，不为凑次数打断叙事。
2. **呼应线**：开头埋的钩子（"我没事"/凉了的茶），结尾必须回收。
3. **温度线**：情绪有弧线，不能一个调门到底（养令：凉 → 暖 → 更暖；音乐、画面色温跟着走）。

## 6. 空白模板（复制即用）

```markdown
# XX · 口播稿（痛点→过程→升华）

时长 X:00 · 约 XXX 字 · 配音/宣讲人：

## 一、痛点（四分钟示例：0:00–0:40）
（设问开场，不寒暄）
> 你有多久/你有没有发现，______（具体人物 + 具体动作的生活切片）？
> 他们总说"______"，但______（矛盾点）。
> 你自己也一样：______（第二切片，最好引用赛题原话"______"）。
> 这不是缺______，是缺______（点破问题本质）。
> 我们的调研：N 份有效答卷中，n 人反馈______（选 1–2 条已核实证据；没有数字就诚实说这是待验证假设）。
> 所以，我们做了 XX：不是______，而是______。（中心论点）

## 二、功能证明（四分钟示例：0:40–3:25）
### 2.1 理念（承，~25s）
> 赛题问："能不能从______变成______？"
> 我们的回答：过去/别人是______；我们是______（对比，最好四宫格可演示）。
> 不是______，而是______。

### 2.2 三步用一遍（转，重头）
> 第一步：______（操作 + 屏幕画面）→ 解决"______"（回扣痛点）。
> 第二步：______（操作 + 画面 + 真实步骤如授权）→ 解决"______"。
>   - 诚实边界：______（本地不上传/仅供参考/非诊断）。
> 第三步：______（操作 + 画面）→ 解决"______"。
> 持续使用：______（成长/反馈机制，7/14/30 天之类）。

### 2.3 副线功能（~25s）
> 引用扣题："______"。双方同意 → 能看见什么 → 边界（非监控/可解绑）。

### 2.4 底线与未来（守，~20s）
> 本次演示的边界：______；对应验证证据：______。
> 下一步（明确是规划）：接入______；异常时只提醒就医，不诊断、不处方、不替代检查。
> XX 负责______；医院负责______。

## 三、升华（四分钟示例：3:25–4:00）
> 我们解决的不是"______"，而是三个具体问题：
> ______、______、______（与第一段痛点逐一对应）。
> （可选，仅填已核实事实）本次完成______，可以现场验证______。
> 我们不______，也不______（边界表态）。
> 我们只想______（具体动作 + 情感结果）。
> 金句：让______，不再______。
> XX——______、______、______。（slogan 定格）
```

## 7. 交稿前自检清单（对照作文评分标准逐项打勾）

**审题扣题**
- [ ] 赛规重点有对应功能和证据；直接引语核对原文，没核对则改成转述。
- [ ] 中心论点一句话能说清，且在痛点段末尾亮明。

**结构（表达自检，不代表评委评分权重）**
- [ ] 痛点、功能证明和价值收束形成闭环，顺序适配赛规。
- [ ] 核心演示获得足够时间，整稿实测不超时。
- [ ] 第二段是操作流（第一步/第二步/第三步），不是功能参数表。
- [ ] 每个功能点都完成"是什么→怎么用→解决哪个痛点"。

**内容与论证**
- [ ] 数据可追溯，样本、分母和限制明确；没有把需求调查写成疗效或留存验证。
- [ ] 至少一个真实场景、一个可运行闭环和一项与评分相关的实现证据。
- [ ] 规划功能全部用"下一步/未来"口径，无已上线包装。

**语言与情感**
- [ ] 开头尽快交代对象和产品；结尾简短、具体且回扣主题，不为凑字数牺牲准确性。
- [ ] 首尾呼应（开头埋的钩子结尾回收）；全篇有统一意象和情绪弧线。
- [ ] 按本人实际语速完整排练，计入操作与停顿；超时先删重复修饰和低权重内容，保留评分相关证据。

**真实性与使用边界（不是声称赛事存在某种一票否决条款）**
- [ ] 不诊断、不处方、不承诺疗效（无"治感冒/治 XX"）。
- [ ] 无手机号/未核实校名/第三方真实身份信息。
- [ ] 视频/隐私表述真实（本地识别、双方同意、可解绑）。

## 9. 像答语文大题一样，让评委容易找到证据

### 9.1 先审题，再写故事

把本场官方规则中的评分维度、权重、时限、允许使用的既有成果、指定技术、材料要求逐项摘到一页。没有公布的权重写“未公布”，不能用本文或别场比赛替代。

为每个评分项填一句回答、一个画面、一个可复查证据。例如技术实现项：本机提取姿态关键点 → 摄像头实测 → 实现代码与设备测试记录。商业项若存在：谁使用、谁付费、当前有什么访谈或试点证据；没有就写验证计划。

MLH 的一份标准规则突出技术、设计、完成度、学习，并鼓励展示实际作品；其另一个赛事条款列出的维度又不同。这正说明不能假定所有黑客松“结构最重要”或统一按商业路演评分。[来源 S3、S4]

### 9.2 小题分点，大题论证

每个功能用一个可复述的短段：**结论 → 现场证据 → 为什么回应痛点 → 必要限制。**

养令例子：“我们把练习反馈做成了看得见、听得到的提示。现在授权摄像头，调整手臂位置，界面反馈随之变化。它针对的是独自跟练时不知道怎么调整的问题；这里是练习辅助，不是专业康复评估。”

不能只说“运用了 AI、RAG、多模态”；那相当于只写术语，没有完成作答。也不能只放录屏不解释，那相当于堆材料，没有分析。

### 9.3 做出三层可理解性，不赌评委一直专注

- **只看开头：** 一句话知道给谁用、解决哪件事、产品长什么样。
- **中途抬头：** 每屏用结论式标题，如“完成后留下记录”，不要只有“功能三”；口头转场说“刚才解决能不能开始，现在解决能不能坚持”。
- **完整看完：** 能复述一个闭环、一个关键实现、一个当前限制和下一步。

“15 秒说明产品”“一屏一个结论”是团队设计约束，不是人类注意力实验结论，也不承诺得分。YC 的清晰表达建议可借鉴，但投资路演要求不等于黑客松要求。[来源 S2、S5]

### 9.4 升华不是突然变大，而是把功能翻译成人的改变

三级收束：刚才完成了什么具体动作 → 它让使用者或家人少了什么困扰 → 回到开头的一句话。只表达合理愿景，不把“希望帮助坚持”改成“已证明长期改善健康”。

三个可选收尾：

1. “让照顾自己，从知道开始，落到今天的一次行动。”——强调行动闭环。
2. “关心不只是多提醒一句，也可以是看见对方今天的小进步。”——强调家庭支持，不声称监测健康。
3. “养令——练对，也练开心。”——保持已有品牌记忆。

### 9.5 彩排验收：不问好不好听，问能否复述

请没参与开发的人听一次，不补充解释，问：给谁用？解决什么？刚才真的演示了什么？哪些还没做？四问答不清就先修结构，再修辞藻。这个练习借鉴 YC 的复述检验，不是正式用户效果研究。[来源 S5]

录一遍完整彩排，连页面加载、点击、停顿与视频都计时。四分钟场可先按 3:40–3:50 完成排练，留操作余量；若赛规允许纯录屏，另备已标注的真实录屏。现场故障先承认，切备用录屏，不把播放录像说成正在实时运行。

## 11. 赛前必做：赞助方、合作方与公开评委背景调研

这项工作应发生在选题与技术选型之前，而不是录口播时临时加品牌名。目标是找到“用户需要、赛事要求、赞助方能力”三者的交集，把真实技术贡献讲清楚。赞助身份不等于评委身份；评委任职公司也不自动等于本场指定技术或评分偏好，均以公开信息与本场规则核对。

### 11.1 一张调研表，服务选型而非堆品牌

| 必填项 | 需要记录的内容 |
|---|---|
| 主体与角色 | 主办、赞助、合作、公开评委及任职机构；官方来源链接和核验日期 |
| 赛事要求 | 总奖或专项奖、指定技术、资格条件、提交材料、截止时间；未公布权重就写未公布 |
| 可用资源 | 准确产品名、模型 ID、API/SDK、官方文档、额度、申请方式和到账时间 |
| 接入可行性 | 开放权限、区域与设备限制、延迟、配额、成本、数据处理要求、额度到期后的运行方式 |
| 产品契合点 | 用在用户流程哪一步，解决什么问题，为什么比不接入更合适 |
| 最小验证 | 一次真实请求、可见输出、错误与降级处理；负责人和预定完成时间 |
| 演示证据 | 对应代码、脱敏调用记录、页面与录屏位置；状态标明候选/已申请/已跑通/已用于 Demo |
| 口播归属 | “谁的什么能力 → 我们如何使用 → 用户得到什么”，对应哪一张画面 |

API Key 只记录领取与配置方式，不把密钥值放进文档、GitHub、PPT 或录屏。官方公开资源及技术文档优先，不猜未公开的合作关系或评委私人偏好。

### 11.2 选择规则：先契合，再验证，再扩展

先查必须满足的技术与奖项条件；在满足条件的候选中，优先接入直接服务核心闭环、能在赛期内跑通、可清晰展示效果的能力。其余资源列为备选。

**不要求把所有赞助方产品都接上。** 每增加一个依赖都要回答：它具体改善哪一步？现场能否稳定演示？若只是多一个 Logo、重复已有能力或让流程更不稳定，就不接。也不承诺“提到赞助方就会加分”；只有本场公开规则才能确定奖项资格与评分要求。[来源 S3 的规则适用范围仍需按本场核对]

执行顺序：查官方名单与规则 → 列资源表 → 选择核心接入点 → 申请权限与额度 → 跑通最小调用 → 接入真实用户流程 → 留存证据 → 写入分镜与口播 → 彩排核对实际调用对象。

### 11.3 让评委一耳朵听见：品牌名、能力名、用途同句出现

在第二段对应功能出现时自然说明，不把全部品牌挤到最后的致谢页。第一次提及用准确产品名，页面同时标注技术归属；后续以解释用户价值为主，不反复念广告。

> “这里我们接入了【赞助方】的【具体产品/模型/API】，负责【具体步骤】。大家现在看到的【输出】，就是它在这一步返回、再由我们【处理方式】呈现的结果，帮助用户【具体收益】。”

如需比较效果，必须有实测再报数字；没有测量就描述实际输出，不说“更准”“提升百分之多少”。同时说明团队自己完成的检索编排、界面、反馈或工程连接，避免把平台能力全算作团队原创。

专项奖提交时，准备一条能追问到底的链：**产品名 → 调用位置 → 输入输出 → 用户价值 → 可复查证据。** 若现场启用了备用模型，按实际情况说明，不能把备用返回结果归给赞助方。

### 11.4 百川案例：把这次的遗漏变成下次的检查项

> 后续更新：2026-09-13 新版网页问答已接入 Baichuan-M3-Plus 医疗检索，见[接入记录与版本边界](百川医疗检索接入-2026-09-13.md)。下文保留的是接入前复盘，不代表当前新版网页状态。

按团队本次反馈，养令并未实际接入所提到的百川医疗搜索相关能力，因此现有口播不能补成“我们已使用百川医疗搜索”。本节只记录复盘与未来流程，不确认该能力当前的准确产品名、开放 API 或本场赞助身份。

下次先核对官方产品文档、赛事名单与权限：如果存在可用且适配的医疗信息检索接口，可把它列为问答知识库检索环节的候选。先验证来源质量、输出是否带可追溯引用及接口限制，再决定是否接入；不要将“调用了聊天模型”表述成“使用了医疗搜索”。

真正跑通后，才把模板填成：“问答检索环节使用了百川的【已核实产品名】，取得【实际返回内容】，由养令【实际处理方式】展示。”未跑通只写计划，不能作为已完成成果。

### 11.5 加入口播交稿前的必检项

- [ ] 已核对公开赞助方、合作方、评委与赛事规则，没有混淆角色。
- [ ] 已筛选可用 API/SDK 与额度，核心接入有真实调用和可演示结果。
- [ ] 每个提到的品牌均对应具体产品、实际功能与证据，不凭配置框或 Logo 宣称使用。
- [ ] 对应功能段能听见“谁的什么能力，用来做什么”，画面同步呈现。
- [ ] 候选、计划、实际使用和备用方案区分清楚；未暴露密钥。
