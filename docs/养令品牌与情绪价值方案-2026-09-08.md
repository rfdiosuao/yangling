# 养令 · 商业品牌与情绪价值方案

2026-09-08 · 讨论整理稿（待团队/行政评审）

> 定位：把「品牌叙事 — 需求证据 — 情绪价值」三条线整理成可落地、可向评委讲述的方案。
> 本文只做方案整理，不修改网站、APK 或线上配置。技术落地另行排期。

---

## 0. 一句话

**养令不是"又一个人体健康提醒工具"，而是"有人在乎你练得对不对、练完还会夸你的养生陪伴"。**

- 实用价值留人：AI 看得懂你的动作、问答有据可依、到点提醒你该歇了。
- 情绪价值吸人：练完开一朵小花、连打七天发芽、每天一个状态签——让人愿意没事上来玩一玩。

品牌一句话候选：**「练对，也练开心」**。

---

## 1. 品牌定位：让评委记住我们的三层设计

"世界上最好的自我介绍是利他"——别人听到"这东西对我有用"就会记住。对评委而言，要的不是功能清单，而是一个"我能带走"的体验。

| 层 | 要解决什么 | 载体 | 评委感知 |
|---|---|---|---|
| 叙事（利他） | 让评委**记住**我们 | 开场故事：爸妈/长辈练八段锦、太极、易筋经时没人指导，我们让 AI 看得懂他们的动作，练完送一朵小花 | 情感记忆点 |
| 证据（真实） | 让评委**相信**我们 | 群调研数字 + 真实群截图（不是"我爷爷说"） | 可信度 |
| 体验（情绪价值） | 让评委**玩起来** | 小花/花园/状态签的即时反馈 | 现场演示的爽感 |

> 判断标准：演示结束 24 小时后，评委还能说出"那个练完开小花的养生 App"——这轮就赢了。

## 2. 需求证据：群调研方案（真实 > 孤证）

### 2.1 问题

- 现状证据是"我爷爷/我奶奶"，属于孤证，评委第一反应是"用户真实需求到底在哪里？"
- 微信群信息无法被工具分析，逐条截图费时且零散。

### 2.2 目标渠道

| 群类型 | 举例 | 调研目标 |
|---|---|---|
| 传统功法 | 八段锦 / 太极 / 易筋经 / 五禽戏 群 | 练功中的具体痛点 |
| 银发养生 | 养生 / 中医 / 穴位 群 | 使用习惯与提醒偏好 |
| 社区健身 | 广场舞 / 银发健身 群 | 长辈 vs 子女的使用场景 |

### 2.3 工具选型

- **问卷星 / 腾讯问卷**：链接发进群，数据自动汇总成图表、可导出 Excel/CSV，AI 与表格工具都能直接分析。
- **不要**用微信群逐条收集（微信生态封闭、数据不可读）。
- 可在 QQ 群、公众号推文内分发，保留"进群时间 + 问卷填写"的可截图证据。

### 2.4 问卷题项草案

1. **筛选**：您的年龄段 / 是否练习过八段锦·太极·易筋经（近一年）
2. **核心痛点（多选）**：练的时候遇到过哪些问题？
   - 练完不知道动作对不对
   - 动作要领记不住
   - 身边没人纠正
   - 坚持不下来 / 想不起来练
   - 膝盖 / 腰部等部位不适，不知道是不是动作问题
3. **功能意愿（多选）**：如果有一个"手机帮你看着练"的 App，最想要？
   - 实时纠正动作
   - 到点提醒我起身活动
   - 记录连续打卡、给点小奖励
   - 养生知识有依据可查
4. **开放题**：练功时最想让"有人"帮你的是什么？
5. **提醒偏好**：您希望以什么形式被提醒？（通知 / 语音 / 定时）

### 2.5 证据链产出

- **数字证据**：N 个群 × M 份有效问卷 → 痛点占比排行（例："64% 的人说练完不知道动作对不对"）。
- **截图证据**：群内真实反馈、问卷填写时间戳、群名称（打码个人信息）。
- **引用规范**：文档中标注"调研样本：X 群 × Y 份，2026-09 收集"。

### 2.6 诚实红线

- **骨架要真**：至少 1-2 个真实群的真实反馈打底，保证被追问"哪个群？"时拿得出截图。
- **包装可美**：在真实数据上做结构化、可视化提炼，不凭空捏造样本量或比例。
- 违反这条的风险：评委或评审组一旦核实造假，品牌信任全毁。

## 3. 情绪价值与激励体系（差异化核心）

### 3.1 设计原则

- **实用留人，情绪吸人**：纠正动作（实用）负责"有用"，小花/花园/状态签（情绪）负责"想用"。
- 参考：Apple Watch 的 HRV 类 App 功能上只是报一个数，但给的是"我现在状态挺好"的确认感——纯情绪价值也能成为购买理由。

### 3.2 三层激励

| 层 | 触发时机 | 反馈 | 目标 |
|---|---|---|---|
| **即时爽感** | 每次完成一杯 / 一动 / 一息 | 屏幕开一朵小花 + 轻量粒子动画 | 每次完成都有一点"爽"，愿意多做 |
| **习惯养成** | 连续打卡 7 / 14 / 30 天 | 芽 → 花 → 小树 → 攒成"我的小花园" | 让坚持变得可见、可炫耀 |
| **状态感知** | 每天打开 App | 今日状态签（节气 × 使用时长生成：活力 / 平静 / 困倦） | 纯情绪价值，一打开就开心 |

### 3.3 激励的两种触发形态

- **及时触发**：完成动作立刻给反馈（动画 + 小花），爽感前置。
- **累计触发**：连续打卡到里程碑给大激励（开花/种树），给"想回来打卡"的理由。
- 两者并行：每天的小确幸 + 每周/每月的大目标。

### 3.4 与现有功能的映射

| 现有能力 | 激励接入点 |
|---|---|
| 「一杯 / 一动 / 一息」打卡（Home） | 打卡完成 → 即时小花动画；写入连续天数 |
| 动作识别完成（Motion） | 达标/完成练习 → 额外奖励标记 |
| 呼吸 60s 计时（一息） | 完成一息 → 小花 + 状态签素材 |
| 使用时长（reminder.js） | 状态签输入之一（今日用了多久） |
| 节气（白露/秋分…） | 状态签的"节气语境"文案 |

## 4. 落地清单（技术映射，排期另行确认）

| 模块 | 说明 | 建议位置 |
|---|---|---|
| 打卡与连续天数存储 | localStorage：`yangling:streak:v1` | `src/mobile/streak.js`（纯函数，可测） |
| 小花/花园动画 | SVG 动画组件，做完动作触发 | `src/mobile/FlowerReward.jsx` |
| 今日状态签 | 节气 × 使用时长 → 状态文案 | `src/mobile/status-sign.js` |
| 激励与提醒联动 | 提醒触发后完成动作 → 小花（打通"提醒—行动—奖励"闭环） | `MobileApp.jsx` 提醒链路 |

优先级建议：**即时爽感（最快见效）→ 习惯养成（连续打卡）→ 状态签（每日陪伴）**。

---

## 5. 与"主动提醒 / 番茄专注"的关系

- 提醒负责"把人叫回来"，激励负责"让人留下"——两者组成完整闭环：
  **提醒到点 → 做完一杯/一动/一息 → 开一朵小花 → 明天还想回来**。
- 番茄专注（午睡/一息定时锁屏）可作为"状态签"的数据来源之一，暂不承担激励主链路。
